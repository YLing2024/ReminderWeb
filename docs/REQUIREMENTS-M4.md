# ReminderWeb M4 需求书：WebDAV 云备份

> 背景：安卓版（上游 `ybhgl/Reminder`）自带「WebDAV 云备份」（设置 → 备份与恢复 → 备份目标：本地 / WebDAV），
> 可把备份包上传到任意 WebDAV 服务器并从中恢复。Web 版目前**只有本地导出/导入**，这是能力缺口，
> 必须补齐，且与本地导出的备份格式、加密方式完全一致（两者产物可互换）。
>
> 本文件是自包含规格：执行者无需任何对话上下文即可实现。

## 1. 目标

在 Web 版里加入 WebDAV 云备份：把与「导出为文件」完全相同的备份 zip 上传到用户自己的 WebDAV 服务器，
并能从该服务器列出、下载、恢复备份。纯前端实现，**不引入后端**。

## 2. 设置项（设置页新增一组「WebDAV 云备份」，风格沿用设置页现有 tonal 分组卡片）

| 项 | 说明 |
| --- | --- |
| 启用云备份 | 开关。关闭时其余项置灰，但不丢失已填内容 |
| 服务器地址 | 完整 URL，含协议与路径，例 `https://dav.example.com/dav/`。允许不带结尾斜杠，内部统一规范化 |
| 用户名 | Basic 认证用户名 |
| 密码 | Basic 认证密码。**UI 默认掩码显示，旁边提供「显示/隐藏」切换**（真触摸事件可切换，不得回弹） |
| 测试连接 | 按钮。发起一次 PROPFIND（Depth: 0）验证凭据与路径；成功显示「连接正常」，失败显示明确原因 |
| 立即上传备份 | 按钮。生成备份（遵守下方「加密」设置）并上传 |
| 从云端恢复 | 按钮。列出远端备份，供选择恢复 |
| 自动备份 | 开关。数据发生变动后延迟 60 秒合并上传一次（节流），上传期间不阻塞 UI |
| 保留份数 | 数字，默认 10，范围 1–100。上传成功后若远端本应用产生的备份超过该数量，删除最旧的 |
| 状态区 | 显示：上次成功时间、上次结果（成功/失败原因）、当前是否在上传 |

## 3. 备份产物（必须与本地导出**逐字段一致**，可直接互换）

- 文件名：`reminder-backup-yyyyMMdd-HHmmss.zip`（与本地导出一致，**不得**改成别的命名）。
- 内容：`metadata.json`（结构见 `docs/REQUIREMENTS.md` 的备份章节，与现有 `src/lib/backup*.ts` 实现保持同一份代码路径）
  - 以及有图片时的 `images/` 目录。
- 加密：复用**现有**加密实现（AES-CBC，密钥 = SHA-256(固定常量逐字节 XOR 90)，密文布局 `[16 字节 IV][密文]`），
  与本地「导出加密备份」使用同一开关状态；**不得**另写一套加密。
- 因此：本功能只负责**传输**，产物的生成与解析一律复用现有函数。

## 4. 协议要求（纯 fetch 实现，不引入 WebDAV 库）

- 上传：`PUT <base>/<文件名>`，`Content-Type: application/zip`，Basic 认证。
  - 上传前先用 `MKCOL <base>` 尝试建目录（已存在返回 405 时忽略）。
- 列目录：`PROPFIND <base>`，`Depth: 1`，请求体询问 `getcontentlength` 与 `getlastmodified`；
  解析 XML 取 `*.zip` 且文件名匹配 `reminder-backup-` 前缀的项，按时间倒序。
  - XML 解析用 `DOMParser`（浏览器原生），**不得**引入 XML 库。
- 下载：`GET <base>/<文件名>`。
- 删除：`DELETE <base>/<文件名>`（仅用于「保留份数」清理，且只删本应用命名的备份文件）。
- 认证头：`Authorization: Basic base64(user:pass)`，用 `btoa(unescape(encodeURIComponent(...)))` 兼容非 ASCII 口令。
- 超时：每请求 `AbortController` 15 秒。

## 5. 错误处理（全部中文、面向普通用户，不得把原始英文堆栈直接抛给用户）

| 情况 | 提示 |
| --- | --- |
| 401 / 403 | 用户名或密码不正确，或该账号无权访问此目录 |
| 404 | 地址不对，服务器上找不到该路径 |
| 405（PROPFIND 不支持） | 该地址不像 WebDAV 服务（服务器拒绝了 PROPFIND） |
| 网络失败 / 超时 | 连不上服务器，请检查地址与网络 |
| CORS（`TypeError: Failed to fetch` 且能判断为跨域） | 服务器未允许跨站访问（CORS）。可改用与本页面同源的地址，或让服务端允许跨域 |
| 响应非 2xx 其它 | 服务器返回 <状态码> |
| zip 解析失败 / 不是本应用备份 | 该文件不是有效的备份包 |

## 6. 凭据存储与安全

- 凭据存 IndexedDB（与其它数据同一套存储层），键名自定并写入 `src/lib/storage.ts` 的说明注释。
- 密码**不得**出现在任何 `console.log` / 错误上报 / 导出的备份包里。
- 「导出为文件」产生的 zip 中**不得**包含 WebDAV 凭据。
- 设置页提供「清除云备份凭据」按钮。

## 7. 恢复语义

- 从云端恢复走**与本地导入完全相同的代码路径**（同一归一化、同一合并/覆盖策略、同一成功提示文案结构）。
- 恢复前给出确认；覆盖模式必须二次确认。

## 8. 视觉与可用性

- 沿用设置页现有分组卡片与表单控件风格（Material 3、圆角、tonal 底色）。
- 窄屏（手机 2 列布局、侧边抽屉）下表单不得溢出、不得被键盘遮挡（输入框聚焦时自动滚动到可视区）。
- 上传/恢复进行中显示进度或至少 pending 态，按钮防重复点击。
- 所有新增文案中文、克制、无 emoji、无技术黑话（不要出现「PROPFIND 失败」这类字样给用户看）。

## 9. 测试要求

- 为 WebDAV 客户端层写单元测试，**mock `fetch`**，覆盖：URL 规范化（带/不带尾斜杠、缺协议）、Basic 头编码（含中文口令）、
  PROPFIND 响应解析（含空目录、含无关文件、含非 zip）、错误码映射（401/403/404/405/超时/网络/CORS 各一条）、
  保留份数裁剪逻辑（多于 N 时删最旧、只删本应用文件）、自动备份节流（连续变动只触发一次）。
- 另写一条集成测试：用 mock 的 WebDAV 服务端（内存实现 PUT/PROPFIND/GET/DELETE）跑「上传 → 列出 → 下载 → 恢复」全流程，
  并断言上传的字节与本地导出**逐字节相同**（同参数下）。
- 现有 142 个测试必须继续全绿。
