# ReminderWeb M5 需求书：应用锁改为通用密码（解除数字限制）

> 背景：当前「应用锁」实现是安卓版的 PIN 思路 —— 只收 **4~6 位纯数字**（`src/lib/pin.ts` 的 `isValidPin` 为 `/^\d{4,6}$/`，
> `AppLockGate.tsx` 与 `SettingsPage.tsx` 都把输入 `replace(/\D/g,'')` 剥成数字、`maxLength={6}`、`inputMode="numeric"`）。
> 站点是对外公开的 Web 应用，仅靠 4~6 位数字守隐私数据太弱，且用户已有自己的通用口令（含字母/符号）。
> 本任务：解除数字限制，改为**通用密码**，并同步把哈希从「无盐 SHA-256」升级为「带盐 PBKDF2」。
>
> 本文件自包含：执行者无需任何对话上下文。

## 1. 密码规则（解除一切字符限制）

- 允许**任意字符**：字母、数字、符号、空格、中文、emoji 均可。
  - **禁止**任何形式的字符过滤（不得再出现 `replace(/\D/g,'')` 之类）。
  - **不得** trim 或规范化用户输入 —— 用户输入什么就校验什么（仅不允许"完全为空"）。
- 长度：**1 ~ 128 字符**（不再有 4~6 位上限）。
  - 输入框 `maxLength={128}`；提交按钮仅在**空**时禁用（不再要求 `length >= 4`）。
  - 允许 1 位密码，但界面上给一句克制的弱口令提示（不阻断、不弹窗）：例如密码框下方灰色小字「建议至少 6 位，混合字母与符号」。
- 「设置密码」入口需要**二次输入确认**（两次输入一致才保存）；「修改密码」需要**先输入当前密码**。

## 2. 输入框与交互

- 锁屏页与设置页的密码输入框一律 `type="password"`，旁边提供**「显示 / 隐藏」切换按钮**；
  - 切换必须真实可用（真触摸事件点一下能切换且不回弹），并能看清当前输入内容。
- 不设 `inputMode="numeric"`、不设 `pattern`、不设 `maxLength={6}`。
- `autoComplete`：解锁页用 `current-password`，设置/确认新密码用 `new-password`。
- 移动端键盘可正常输入字母符号；输入框聚焦时不被键盘遮挡（沿用现有滚动到可视区的做法）。
- 解锁失败提示保持克制（例如「密码不正确」），**不得**提示"应为数字"之类。

## 3. 哈希与存储（安全升级）

- 新算法：**PBKDF2-SHA-256，16 字节随机盐，迭代次数 210_000，导出 32 字节**（用 `crypto.subtle.deriveBits` 实现，不引入依赖）。
- 存储结构（写在 `src/lib/storage.ts` 说明注释里）：
  ```
  { v: 2, algo: 'PBKDF2-SHA-256', salt: <base64>, iterations: 210000, hash: <base64> }
  ```
- **向后兼容**：若本地存的是旧格式（v1：`sha256('reminderweb-pin:' + pwd)` 的 hex 字符串），
  解锁时先用旧算法校验；**校验成功后自动改写为 v2**（需要用户这次输入的明文，用完即丢）。
- 密码与盐、哈希**只存本地 IndexedDB**：不联网、不进日志、不进任何导出产物。
- 「导出为文件」的 zip 中**不得**包含应用锁相关字段（补一条测试断言）。
- 「清除应用锁」需当前密码；「忘记密码」路径只允许**清空全部本地数据**并明确二次确认（文案讲清后果）。

## 4. 文案调整

- 界面上一律称「密码 / 应用锁密码」，不再出现「PIN 码」字样（锁屏页、设置页、错误提示、按钮）。
- `README.md`：
  - 「与安卓版的差异」表里 `指纹 / 人脸解锁 | 改为 PIN 码应用锁（后续可扩展 WebAuthn）` 这一行必须改为「改为**应用锁密码**（任意字符，本地 PBKDF2 加盐存储）」。
  - 「功能」区相应措辞同步。

## 5. 测试（现有 142 条必须继续全绿）

- `isValidPassword`（替换 `isValidPin`）：任意字符均合法 —— 至少覆盖 `'1234'`、`'a'`、`'My Pass!@#'`、`'中文密码'`、`'🔒🔒'`、含前后空格的 `'  x  '`；非法仅 `''`；`129` 字符应拒绝、`128` 字符应通过。
- 哈希：同一密码两次 `hashPassword` 得到**不同**盐与不同 hash；`verifyPassword` 对正确密码为真、错误密码为假；含中文/emoji/空格的密码正确往返。
- 兼容：构造一条 v1 旧哈希记录，断言用旧密码可解锁，且解锁后存储被升级为 `v: 2`；用错误密码则保持 v1 不变。
- 设置流程：设置（含二次确认不一致应报错）、修改（当前密码错应拒绝）、清除（需正确密码）。
- 导出备份不含应用锁字段（断言序列化结果里没有 `v`/`salt`/`hash`/`iterations` 等键）。
- 组件层测试：输入框为 `type="password"`、可切换显示、`maxLength` 为 128、空输入时提交禁用。

## 6. 兼容与迁移注意

- 现有已设置锁的用户（本地已有 v1 PIN）：升级后仍能用自己的旧 PIN 进入，并在首次成功解锁后自动升级为 v2；**不得**因升级导致老用户被锁在门外。
- 若存储里同时存在 v1 与 v2 字段冲突，以可校验成功者为准。
